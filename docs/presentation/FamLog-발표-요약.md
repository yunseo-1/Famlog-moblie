# FamLog(팸로그) 발표용 요약

> 이 파일은 발표 자료(슬라이드)를 만드는 AI에게 주는 입력 자료다. 2026-11-23 기준.
> 근거: 저장소 `docs/handoff/HANDOFF.md`(진행 현황), `docs/spec/`(통합 사양서 v2.0), `CLAUDE.md`.
> 슬라이드는 한국어로, 발표 시간에 맞춰 10~15장 정도를 권장한다. 마지막에 "슬라이드 구성안"이 있다.

---

## 1. 한 줄 소개

**가족 전용 단체 채팅 + 구성원별 일정 + 맛집·장소 + 앨범을 하나로 묶고,
채팅에서 일정·기념일·할 일·장소를 AI가 알아채 "등록 후보"를 만들어 주는 Android 가족 앱.**

- 목표: Google Play 출시 (v1.0 목표 2027년 2월 중순)
- 1인 개발자 + AI 코딩 도구(Claude Code)로 개발 중

## 2. 문제와 해결

| 문제 | FamLog의 해결 |
|---|---|
| 가족 약속이 단톡방 대화 속에 묻혀 사라진다 ("이번 토요일 11시에 할머니 댁 가자") | AI가 대화에서 일정·할 일·장소·기념일을 찾아 **등록 후보 카드**로 보여 준다 |
| 일정 앱, 메신저, 지도 앱, 사진 앱이 따로 놀아서 다시 입력해야 한다 | 채팅·캘린더·장소·앨범을 한 앱에서, 가족 그룹 단위로 |
| AI가 마음대로 등록하면 믿을 수 없다 | **AI는 절대 직접 등록하지 않는다.** 사람이 확인·수정 후 승인해야 등록 |
| 가족이라도 각자의 개인정보가 있다 | 내 메시지 분석 제외, 미리보기 숨기기, 앱 잠금, 내 데이터 내보내기·계정 삭제 |

## 3. 핵심 차별점: AI 등록 후보 흐름

```
채팅 메시지 → (서버) AI가 원문 표현만 추출 → 서버 코드가 날짜 계산·구성원 매칭·장소 확정
→ 등록 후보(PENDING) 생성 → 채팅방에 후보 카드 + 근거 메시지 강조
→ 사용자가 확인·수정 → [등록] 승인 → 그때 실제 일정·할 일·장소가 만들어짐
```

- **AI 제안 표시 + 근거 인용**: 카드에 "AI 제안" 배지, 어느 메시지에서 찾았는지 인용·강조
- **추정 배지**: 확실하지 않은 값(예: 시간 미정)은 "추정"으로 표시
- **5분 되돌리기**: 승인·무시 직후 칩에서 되돌리기
- **기존 일정 변경 감지**: "할머니 댁 11시 말고 12시로 하자" → 기존 일정 [바꾸기] 후보(변경 전→후)
- **할 일 완료 감지**: "자동차 점검 맡겼어" → [완료] 후보
- **제안함**: 대기 중인 후보를 한곳에서 모아 보기(앱바 ✨ 배지)
- **원문 보기**: 등록된 일정·할 일·장소에 "채팅에서 등록" 태그 → 누르면 근거 메시지로 이동
- **신고**: AI 결과가 틀리거나 부적절하면 앱 안에서 신고
- **분석 동의**: 그룹 AI 분석 켜기 전 전송 범위·국외 이전 안내, 개인은 "내 메시지 분석 제외" 가능
- 날짜 해석 기준은 근거 메시지의 **발송 시각(서울 시간)**. LLM 프롬프트·응답 원문은 저장하지 않는다.

## 4. 기능 목록 (앱, 구현 완료)

**계정·그룹**
- 카카오·Google 소셜 로그인, 만 14세 이상 확인, 가족 그룹 만들기·초대 코드 참여, 그룹 전환
- 구성원 관리: 권한 바꾸기, 그룹장 넘기기, 내보내기, 신고 / 그룹 나가기·삭제
- 로그인 기기 관리: 기기 목록, 다른 기기 원격 로그아웃, 새 기기 로그인 알림

**채팅 (그룹당 단체방 1개, 1:1 없음)**
- 실시간(STOMP/WebSocket), 오프라인 캐시·재전송, 읽음·답장·공감·삭제(5분)
- 사진 30장·동영상 묶음 전송(백그라운드 업로드), 전체 화면 보기·재생
- 장소 카드 공유, AI 후보 카드

**캘린더·할 일**
- 월·목록 보기, 구성원 필터, 공휴일, 반복 일정, 겹침 안내, 일정 리마인드 푸시
- 할 일: 담당자 필터, 완료 체크(채팅방에 알림)

**장소**
- 맛집·장소 공유, 지역·공유한 사람·카테고리 필터, 다녀왔어요·가고 싶어요
- 카카오 지도·화면 영역 핀, 내 주변(위치 약관 동의, 대략적 위치만)

**알림**
- FCM 푸시: 채널 4개(채팅·일정·AI 제안·시스템), 그룹 묶음, 알림 누르면 해당 화면으로
- 알림 설정: 미리보기 숨기기, 방해 금지 시간, 그룹별 알림 끄기

**개인정보·보안 (출시 요건 포함)**
- 동의 내역·철회, 내 데이터 내보내기(ZIP, 7일 링크, 내 것만), 계정 삭제(30일 유예·복구), 웹 삭제 안내(Google Play 요건)
- 앱 잠금(지문·얼굴·휴대폰 잠금, 1분), 최근 앱 미리보기 가리기
- 강제 업데이트·공지, 신고

**다음 단계(미구현)**: 앨범 탭 고도화, 이야기(AI 스토리·영상), 출시 준비(S22: 서명·정책 문서·스토어)

## 5. 기술 구조

| 영역 | 기술 |
|---|---|
| 앱 | Kotlin, Jetpack Compose, MVVM + Hilt, Retrofit/OkHttp, STOMP(직접 구현), Room, Coil, Kakao Map SDK, Photo Picker, FCM, WorkManager, BiometricPrompt. minSdk 26 / targetSdk 37 |
| 서버 | Java 21, Spring Boot 4.1, Spring Security(JWT ES256), WebSocket(STOMP), JPA + JdbcTemplate, Flyway |
| AI·미디어 워커 | Python 3.12, Redis Streams 소비자, Claude API(claude-haiku-5-5, 구조화 출력), FFmpeg·Pillow |
| 데이터 | PostgreSQL 16 + PostGIS + pgvector, Redis 7, S3 호환 저장소(로컬 SeaweedFS) |
| 인프라 | Docker Compose, GitHub Actions CI |

저장소 3개: 앱(이 저장소), 백엔드, 문서(사양서·API 계약 openapi.yaml)

```
[Android 앱] ──REST/JSON──▶ [Spring Boot API] ──▶ PostgreSQL / Redis / S3
     ▲   └──STOMP(WebSocket) 실시간──┘      │
     └──── FCM 푸시 ◀───────────────────────┤
                                  Redis Streams
                                        ▼
                         [Python 워커: AI 인식·사진/동영상 처리]
```

**보안 원칙 (사양서 9장)**
- 모든 그룹 데이터 접근은 권한 검사(비구성원 403, 다른 그룹 리소스는 404로 존재 숨김)
- 토큰은 Android Keystore로 암호화 저장, 재발급은 1회 동기화(재사용 감지 시 전 기기 로그아웃)
- 메시지 본문·토큰·좌표 등 개인정보를 로그에 남기지 않음
- 사진은 Photo Picker만(전체 사진 권한 없음), 위치는 대략적·포그라운드만

## 6. 개발 방식 (발표 포인트)

- **사양서 주도 개발**: 통합 사양서 v2.0(21개 장)에 기능 ID(예: SCH-02), API, 데이터, 인수 기준을 먼저 정의
- **AI 코딩 에이전트 2개 협업**: 앱 세션과 백엔드 세션(Claude Code)이 서로 메시지로 API 계약·변경을 주고받음.
  사람(개발자)이 각 단계 계획을 승인하고, 커밋·머지는 사람의 지시로만
- **기능 하나씩**: `/feature 기능ID` → 사양 요약·질문 → 계획 승인 → 구현 → 테스트 → 실기 확인 → PR
- **실기(실제 계정) 확인**: 에뮬레이터 + 로컬 서버로 로그인·삭제·복구·내보내기·잠금 등을 실제로 확인하고, 발견한 문제를 바로 수정
  - 예: 그룹이 없는 사용자는 계정 삭제에 닿을 수 없던 문제를 실기에서 발견 → 수정(Google Play 요건)
- **테스트로 지킨다**: 테스트를 지우거나 약하게 바꿔서 통과시키지 않는다

## 9. 시연 시나리오 (약 5분)

> 준비: 로컬 서버 실행, 에뮬레이터에 윤서 계정 로그인, "우리가족" 그룹(2명). 앱 잠금은 꺼 두거나 PIN을 알고 시작.
> AI 후보 시연(2~4번) 서버 준비:
> - 그룹 설정에서 **AI 분석 켜기**(안내 확인). 꺼져 있으면 후보가 생기지 않는다
> - 로컬 워커가 실제 LLM 사용: `infra/.env`에 `LLM_PROVIDER=anthropic`과 API 키(이미 설정됨). 서버 :8080 실행 중이어야 함
> - 타이밍: 날짜·시간 표현이 있는 메시지는 대화가 **30초 멈추면** 분석 → 카드까지 약 30~40초. 연달아 말하면 기다린다
> - 3번 [바꾸기]는 2번 일정을 먼저 **등록**해야 나온다(60일 안, 반복 아닌 일정)
> - 비용: 한 번에 1센트 미만(평가 60건 전체 약 $0.01). 월 상한 $20, 그룹당 하루 100회

1. **채팅 탭** → "우리가족" 채팅방 (그룹 목록, 마지막 메시지·안 읽은 수)
2. 메시지 보내기: **"이번 토요일 11시에 할머니 댁 가자"**
   → 잠시 뒤 **AI 후보 카드**(AI 제안 배지, 근거 인용, 날짜는 발송 시각 기준으로 계산) → [등록] → 캘린더에 생김
3. **"할머니 댁 11시 말고 12시로 하자"** → 기존 일정 **[바꾸기]** 후보(11:00 → 12:00)
4. **"아빠가 이번 주에 자동차 점검 맡겨야 해"** → 할 일 후보(담당자: 아빠) / **"자동차 점검 맡겼어"** → [완료] 후보
5. **캘린더 탭**: 등록된 일정의 "채팅에서 등록" 태그 → 누르면 근거 메시지로 이동
6. **장소 탭**: 지도·리스트, 장소 카드 공유
7. **제안함(✨)**: 대기 중인 후보 모아 보기
8. **설정**: 알림(방해 금지·그룹 끄기), 개인정보·보안(로그인 기기·내보내기·계정 삭제), 앱 잠금
9. **앨범·이야기 탭**: 탭을 눌러 "준비 중" 화면을 보여 주고, 슬라이드의 **디자인 시안**(05_album, 06_story)으로 설명한다.
   "AI 후보까지는 지금 동작하는 기능, 앨범·이야기는 설계를 마친 다음 단계"로 나눠 말한다. (앱·서버 모두 아직 구현 전이라 데이터를 넣어도 화면에 나오지 않는다)
10. (선택) 사진 여러 장 보내기, 푸시 알림 눌러 채팅방 열기

시연 실패 대비: 미리 녹화한 화면, `docs/design/screenshots/`의 화면 이미지

## 11. 슬라이드 구성안 (예시, 12장)

1. 표지 — FamLog(팸로그), 한 줄 소개, 발표자
2. 문제 — 가족 약속이 단톡방에 묻힌다 (대화 예시 말풍선)
3. 해결 — 채팅·캘린더·장소·앨범을 하나로 + AI 등록 후보
4. 핵심: AI 등록 후보 흐름 다이어그램 (3장 흐름) + "AI는 직접 등록하지 않는다"

## 12. 백엔드

**구조**: Spring Boot API(모듈: auth·group·chat·schedule·todo·place·candidate·media·notification·report·admin) + Python 워커(AI 인식·사진/동영상 처리)를 Redis Streams로 연결. 실시간은 STOMP, 서버 여러 대는 Redis Pub/Sub 중계.

**AI 인식 파이프라인**
```
메시지 → 규칙 필터·대화 멈춤(30초) 감지 → 분석 대상만(분석 제외 구성원·끈 그룹 제외, 개인정보 마스킹) 워커로
→ LLM은 원문 표현만 추출("이번 토요일", "11시", "아빠") → 서버 코드가 날짜(발송 시각 기준)·구성원·장소·기존 일정 매칭 확정
→ 등록 후보(PENDING) → 사람이 승인해야 실제 등록
```
- 평가셋 60건(변경·완료·인젝션 포함): 일치 100%, 오탐 0%, 날짜 정확도 100% / 비용 상한·그룹별 하루 상한
- LLM 프롬프트·응답 원문은 저장하지 않음

**보안**
- `GroupAccessChecker`: 모든 그룹 데이터 접근을 한곳에서 검사. 비구성원은 403, 다른 그룹 리소스 id는 404(존재 숨김)
- JWT ES256(키 교체 가능), Refresh 회전·재사용 감지 시 전 세션 폐기, 원격 로그아웃은 Access 토큰에도 즉시 반영(WebSocket도 끊김)
- 로그 마스킹(본문·토큰·좌표), 요청마다 traceId, 업로드 파일 형식 검사·GPS 태그 제거, 초대 코드 실패 잠금

**운영**
- 배치: 계정 30일 파기, 삭제 그룹 파기, 붙지 않은 업로드·삭제된 메시지 미디어 정리, 보관 기간 정리(세션 90일·위치 확인자료 6개월·감사 로그 1년 등), 내 데이터 내보내기 ZIP 생성
- 안정성: 멈춘 스트림 메시지 회수·DLQ, 푸시 재시도, 멈춘 AI 요청 정리
- 관리자 도구(토큰 + 정적 페이지): 신고 처리, 공휴일, 앱 버전·강제 업데이트, 기능 플래그, 감사 로그, AI 비용 배너
