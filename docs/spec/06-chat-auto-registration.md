# 6. ⭐ 채팅 기반 자동 등록 상세 (ARC)

> **핵심 원칙: AI는 절대 임의로 등록하지 않는다.** 모든 항목은 **탐지 → 등록 후보 생성 → 근거 메시지 표시 → 사용자 확인/수정 → 승인 후 등록** 5단계를 거친다. 승인 전 후보는 캘린더·할 일·장소 목록에 나타나지 않고 `registration_candidates`에만 저장된다.

## 6.1 인식 대상

| 유형 | 코드 | 필수 | 선택 | 등록 위치 |
| --- | --- | --- | --- | --- |
| 일정 | SCHEDULE | 제목, 날짜 | 시작·종료 시간(없으면 종일), 장소, 참석자 | 캘린더 |
| 기념일 | ANNIVERSARY | 제목, 월·일 | 대상 인물, 양력/음력, 미리 알림 | 캘린더(매년 반복) |
| 할 일 | TODO | 제목 | 담당자, 기한 | 할 일 |
| 맛집·장소 | PLACE | 장소명 | 지역, 카테고리, 추천 의견, 추천한 사람 | 장소 목록 |

필수 항목이 빠진 후보도 만들되 `missingFields`로 표시하고, 사용자가 채워야 등록된다.

## 6.2 처리 단계

```
① 탐지            ② 후보 생성                 ③ 근거 표시          ④ 확인/수정          ⑤ 승인 후 등록
규칙 필터(서버)    LLM 추출(원문 표현만)        후보 카드 +           [등록][수정][무시]   한 트랜잭션:
+ 30초 멈춤        → 서버 정규화(날짜·구성원·장소)  근거 인용·강조       수정 폼 검증         실제 항목 생성
+ 보조 배치 분석   → 검증 → 중복 제거 → 저장                                                + 시스템 메시지 + 푸시
```

### ① 탐지

- 1차 규칙 필터(비용 없음): 날짜·시간 표현(토요일, 내일, 다음 주, 11시, 15일), 할 일 표현(\~해야 해, \~맡겨, \~사와, 잊지 말고), 장소 표현(맛있더라, 가볼 만해, \~집, \~카페, 지도 링크), 기념일 표현(생신, 생일, 기념일, 제사, 기일).
- LLM 입력: 분석 구간 + 앞 맥락 최대 20개 + 구성원 목록(ID·역할·호칭) + 메시지별 발송 시각. **그룹 AI 분석이 꺼졌거나 발신자가 개인 동의를 끈 메시지는 보내지 않는다.**
- 전송 전 마스킹: 전화번호, 계좌번호, 카드번호, 주민등록번호 패턴은 `[전화번호]` 등으로 치환 (9.7).

### ② 후보 생성: 정규화 규칙 (서버 코드가 계산)

| 항목 | 규칙 |
| --- | --- |
| 상대 날짜 | 근거 메시지 **발송 시각**(Asia/Seoul) 기준. "이번 토요일" = 이번 주(월\~일)의 토요일, 이미 지났으면 다음 주. "다음 주 토요일" = 다음 주의 토요일. "15일" = 이번 달 15일, 지났으면 다음 달. "내일/모레/글피" 지원 |
| 기간 표현 | "이번 주에" → 기한 이번 주 일요일, "주말까지" → 일요일, "이번 달 안에" → 말일 |
| 오전/오후 생략 | 1\~6시 → 오후, 7\~11시 → 오전, 12시 → 낮 12시. 아침·저녁·밤 단서가 있으면 따른다. 추정값은 `inferred` |
| 참석자·담당자 | 아빠/엄마/아들/딸 → family_role, 큰아들·막내 → family_title. 같은 역할 여러 명이면 모두 후보로 보여주고 사용자가 고른다. "가자/우리" → 그룹 전체(추정) |
| 장소 | 장소명+지역 힌트로 카카오 로컬 검색 → 상위 3개 저장, 1개면 자동 선택. "할머니 댁"은 별칭 장소(PLC-06)와 매칭, 없으면 텍스트 |
| 카테고리 | 카카오 카테고리 → 앱 카테고리 변환표 |
| 추천 의견 | 원문의 평가 표현을 짧게 요약, 추천한 사람 = 근거 메시지 발신자 |

- 검증: 과거 날짜 일정, 존재하지 않는 구성원 ID, 스키마 오류는 버린다.
- 중복 제거: `dedupKey` = 유형 + 정규화 제목 + 날짜(또는 카카오 장소 ID). 같은 후보·등록 항목이 있으면 근거만 추가. 무시한 후보와 같으면 만들지 않는다.
- 신뢰도: 0.75 이상 → 채팅방 카드 / 0.5\~0.75 → 제안함(SCR-14)에만 / 0.5 미만 → 버림.

### ③ 근거 표시 · ④ 확인/수정 · ⑤ 등록

- 카드는 마지막 근거 메시지 아래에 붙고, 근거 인용(발신자·시각)을 보여준다. 누르면 원문으로 스크롤하고 추출 부분을 강조한다.
- AI 추정값은 "추정" 배지와 흐린 글씨. 카드 하단에 작게 "AI 제안" 표시와 [신고] 메뉴.
- [수정]은 추출값이 채워진 폼(SCR-13). 필수 누락·장소 후보 여러 개면 [등록]도 폼을 연다.
- 먼저 처리한 사람이 반영된다(낙관적 잠금). 다른 사람 화면에서는 "엄마가 등록했어요"로 바뀐다.
- [무시] 사유(이미 등록함 / 농담이었음 / 틀린 내용)는 선택. 만료: 일정은 일정 시각 경과, 나머지는 7일.
- 승인 API 한 트랜잭션: 실제 항목 생성 → 근거 연결 → 후보 APPROVED. 채팅방 시스템 메시지 + 참석자·담당자 푸시. 5분 안에 [되돌리기].

## 6.3 예시와 기대 결과 (기준일 2026-11-12 목)

| 원문 (발신자) | 기대 결과 |
| --- | --- |
| "이번 토요일 11시에 할머니 댁 가자" (엄마) | SCHEDULE · 11/14(토) 오전 11:00 · 할머니 댁 방문 · 참석: 가족 전체(추정) · 오전 추정 |
| "아빠가 이번 주에 자동차 점검 맡겨야 해" (엄마) | TODO · 자동차 점검 맡기기 · 담당: 아빠 · 기한 11/15(일)(추정) |
| "잠실에 있는 OO칼국수 정말 맛있더라" (아들) | PLACE · OO칼국수 · 서울 송파구 · 맛집 · "칼국수가 정말 맛있음" · 아들 추천 |

## 6.4 후보를 만들지 않는 경우

| 상황 | 예 | 처리 |
| --- | --- | --- |
| 지난 일 | "어제 할머니 댁 갔었지" | 후보 없음 (스토리 재료로만) |
| 정해지지 않은 질문 | "토요일에 시간 돼?" | 동의 답장(좋아/그래)이 나오면 그때 생성. v1.1부터 [투표 만들기] 제안 |
| 농담·가정 | "언젠가 달에 가자 ㅋㅋ" | 버림 |
| 부정 평가 장소 | "거기 별로더라" | 맛집 후보 없음 |
| 이미 등록·무시됨 | 같은 일정 재언급 | 근거만 추가 |
| 변경 요청 | "11시 말고 12시로 하자" | 기존 일정의 수정 후보(변경 전·후 표시) |
| AI 분석 제외 메시지 | 동의를 끈 사람의 메시지 | LLM 전송 자체를 하지 않음 |

## 6.5 인수 기준 (AR)

| 번호 | 조건 |
| --- | --- |
| AR-1 | 6.3 예시를 보내면 대화가 멈춘 뒤 1분 안에 기대 결과와 같은 카드가 근거 메시지 아래 나타난다 |
| AR-2 | 카드가 떠 있는 동안 캘린더·할 일·장소 목록에는 아무것도 추가되지 않는다 |
| AR-3 | 근거 인용과 발신자·시각이 보이고, 누르면 원문으로 이동해 추출 부분이 강조된다 |
| AR-4 | [수정]에서 12:00으로 바꿔 등록하면 12:00으로 저장되고 suggestion_feedback에 EDITED가 기록된다 |
| AR-5 | 필수 항목이 빈 후보는 채우기 전 등록되지 않는다 (서버 422) |
| AR-6 | 두 사람이 동시에 [등록]해도 항목은 하나, 늦은 쪽은 "이미 엄마가 등록했어요" |
| AR-7 | [무시]한 내용을 다시 말해도 새 카드가 생기지 않는다 |
| AR-8 | 6.4 테스트 문장 전부에서 후보가 생기지 않는다 |
| AR-9 | 날짜 계산 단위 테스트 30개 이상 통과 (요일별, 월말, 연말: 12/31(목)에 "다음 주 월요일" → 2027-01-04(월)) |
| AR-10 | AI 분석을 끈 그룹·개인의 메시지로는 LLM 호출 로그가 없다 |
