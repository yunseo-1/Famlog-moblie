---
description: 기능 ID 하나를 통합 사양서 기준으로 계획하고 구현한다
argument-hint: <기능 ID> (예: SCH-02)
---

기능 $ARGUMENTS 작업을 시작한다.

1. `docs/spec/README.md`의 "기능 ID → 읽을 곳" 표를 보고, $ARGUMENTS에 해당하는 절을 모두 읽는다.
   (기능 요구사항 → 데이터 → API → 인수 기준, 그리고 화면 목록 03장, 디자인 맵 ../docs/design/figma-map.md)
2. 읽은 내용을 5줄 이내로 요약하고, 사양에서 결정되지 않았거나 애매한 점이 있으면 질문 목록으로 먼저 보여준다.
3. 구현 계획을 보여준다: 변경·추가할 파일, 만들 테스트 목록(ViewModel 단위 테스트, 필요하면 Compose UI 테스트), 사용할 API(openapi.yaml 기준).
   **내가 승인하기 전에는 코드를 고치지 않는다.**
4. 승인 후 구현하고, 테스트를 실제로 실행해 출력 결과를 보여준다. 테스트를 지우거나 약하게 바꿔서 통과시키지 않는다.
5. 사양서 18장의 해당 인수 기준을 체크리스트로 보여주고 각 항목을 어떻게 확인했는지 적는다.
6. 커밋 메시지(`feat($ARGUMENTS): 요약`)를 제안하고, 서버 API가 아직 없거나 계약과 다르면 알려준다.

범위 밖 모듈을 고쳐야 하면 멈추고 먼저 물어본다.
